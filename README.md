# Тестовое задание: аванс по договору

## Решение: установка и запуск

Нужен **Python 3.10 или новее** (проверено на 3.11 и 3.14). Сторонних библиотек нет, `pip install` не нужен.

1. Распакуйте архив и перейдите в папку проекта:

   ```bash
   cd candidate-B
   ```

2. Постройте отчёт на дату. На Windows вместо `python` можно писать `py`, на macOS/Linux - `python3`:

   ```bash
   python main.py --date 2026-11-10
   ```

   Дату можно указать и по-русски: `python main.py --date 10.11.2026`. События, датированные днём отчёта, учитываются.

3. Результат появится в папке `output/`. Краткая сводка также печатается в консоль.
   - `output/report_2026-11-10.csv` - по каждой работе: цена, выплачено, осталось оплатить, в очереди; итоги по договорам; раздел «ЗАМЕЧАНИЯ» с расхождениями, переплатами и нераспределёнными платежами;
   - `output/payments_2026-11-10.csv` - каждый платёж: статус на дату и куда распределён.

Другие примеры:

```bash
python main.py --date 2026-11-12
```

```bash
python main.py --date 2026-09-05 --out reports
```

```bash
python main.py --date 2026-11-10 --csv-style standard
```

```bash
python main.py --date 2026-11-10 --data path/to/other/data
```

Отчёт на 12.11 показывает переплату по D-2, а отчёт на 05.09 - момент до возврата P-2.

Параметры:

| Параметр | Что делает |
|---|---|
| `--date` | дата отчёта, обязательно |
| `--data` | папка с CSV, по умолчанию `data/` проекта |
| `--out` | папка для отчётов, по умолчанию `output/` проекта |
| `--csv-style` | `excel` (по умолчанию: `;`, десятичная запятая, UTF-8 с BOM - открывается двойным щелчком в Excel с русскими настройками) или `standard` (`,` и точка) |

Справка: `python main.py --help`. Коды выхода: 0 - успех, 2 - ошибка в аргументах или исходных данных (сообщение указывает файл и строку), 3 - файл отчёта открыт в Excel и не может быть перезаписан.

Тесты (стандартный `unittest`):

```bash
python -m unittest -v
```

Файлы решения:

| Файл | Что там |
|---|---|
| `main.py` | точка входа |
| `contract_report/loader.py` | чтение и проверка CSV, суммы в `Decimal` |
| `contract_report/engine.py` | статусы на дату, распределение платежей, проверки и замечания |
| `contract_report/export.py` | CSV-отчёты и сводка в консоль |
| `contract_report/cli.py` | разбор параметров командной строки |
| `tests/` | автотесты: реальные данные на разные даты, синтетические случаи, CSV и CLI |
| `output/` | готовые отчёты на 10.11.2026 |
| `DECISIONS.md` | решения и допущения |
| `NOTE_FOR_ACCOUNTANT.md` | записка бухгалтеру |

Исходные файлы в `data/` программа только читает.

# Исходное задание

Около 2-3 часов. Работа - в Claude Code.

## Контекст

Компания заказывает работы у подрядчиков: съёмки, дизайн. Договор с подрядчиком - это общая сумма на несколько работ. Платим по договору авансом и остатками, иногда платёж привязан к конкретной работе.

Письмо бухгалтера:

> Мне нужен отчёт: по каждой работе - сколько уже выплачено и сколько осталось оплатить, и итог по каждому договору. Сейчас считаю в таблице руками и путаюсь: платежи по договору ни к какой работе не привязаны, а мне надо понимать, за что мы уже рассчитались. Отчёт нужен на дату, для проверки - на 10.11.2026.

## Что есть

Папка `data/`: договоры, работы, платежи и описание формата в `FORMAT.md`.

Бухгалтер в отпуске и на связи не будет, других источников, кроме `data/`, нет. Где данных не хватает, решите сами и запишите допущение в `DECISIONS.md`.

## Что сдать

1. **Программа** на Python или TypeScript - скрипт, CLI или маленький HTTP-сервис, на ваш выбор. По файлам из `data/` и дате она строит отчёт:
   - по каждой работе: цена, выплачено, осталось оплатить;
   - по каждому договору: итоги.

   Напишите, как её запустить: мы запустим сами.

2. **Файл `DECISIONS.md`** - решения, которые вы приняли по ходу работы. По каждому решению коротко:
   - что решали;
   - какие были варианты;
   - что выбрали и почему;
   - что изменится в отчёте, если выбор окажется неверным.

   Пример оформления на постороннюю тему:

   > **Формат отчёта.** Варианты: таблица в консоли или файл CSV. Выбрал CSV: его можно открыть в таблице. Если неверно, поменяется только вывод, расчёт останется прежним.

3. **Записка бухгалтеру** на 5-10 строк простым языком: как читать отчёт и что ей нужно подтвердить, когда вернётся.

4. **Полный транскрипт работы с Claude Code** - экспорт командой `/export`, без правок. Если сессий было несколько - все. Ключи и пароли, если попали в сессию, можно вырезать.

Интерфейс, база данных и docker не нужны. Деньги считайте точно, до копейки, без float.

Не успели всё - напишите, что осталось и что бы вы сделали дальше.
